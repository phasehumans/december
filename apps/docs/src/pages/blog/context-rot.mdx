every few months a model ships with a bigger context window. the context window is how much text a model can read at once. it is counted in tokens, which are small pieces of words. a few years ago it was 8k tokens. now it is 1m. the pitch is simple: put your whole codebase in the prompt and let the model sort it out.

i believed this for a while. then i watched agents get worse as i gave them more.

## long is not the same as good

chroma tested this in a report called [_context rot_](https://www.trychroma.com/research/context-rot). they gave models longer and longer inputs and asked them to find one fact. as the input grew, the models found the fact less often. that part is not a surprise. the surprise is how fast it falls when the question and the answer use different words.

the usual long-context test is called needle in a haystack. you hide one sentence in a lot of unrelated text, and you ask the model to find it. but the question usually repeats the words of the hidden sentence. so the model only has to match words. that is grep with extra steps. models are good at it, and the scores look great.

real questions are not like that. you do not ask an agent for `validateSessionToken`. you ask it to "fix the login bug". the words in your question are not the words in the code. that is the case where long inputs hurt most.

## code is full of look-alikes

chroma split extra text into two kinds. noise is text about something else, and models ignore it fairly well. distractors are text on the same topic that looks like the answer but is wrong. models do not ignore those.

a codebase is mostly distractors. there is `getUser` and there is `getUserById`. there is the old auth module that nobody deleted. there are test mocks that copy the real interfaces line for line. load fifty files into a prompt, and you hand the model five good-looking answers and ask it to pick one. when it picks the wrong one, it is not careless. you set it up to fail.

## give it less

so the job is not to give the model more. the job is to give it less, and the right less.

a good agent searches first and opens the few files that matter. it does not keep a long terminal log in view after the step is done, because most of that log is no longer true. and it checks its work against things that do not care how long the prompt is: the compiler and the tests. a failing test fails at token 100 and at token 100,000.

a bigger context window is a bigger haystack. it is not a better way to search it.
