the first ai coding tools worked like autocomplete with ambition. you wrote a prompt. the model wrote 200 lines in one pass. then you spent the afternoon finding the functions it made up.

that works for boilerplate. it does not work for a refactor across twelve files.

what made agents useful was not mainly better models. it was the loop.

## a model can't take it back

a language model writes one token at a time. a token is a small piece of a word, and each one depends on the ones before it. there is no undo. if the model assumes the wrong database schema at token 40, every token after that builds on the mistake. the model does not notice. it gets more confident.

## write, check, fix

in 2023, madaan and others published [_self-refine_](https://arxiv.org/abs/2303.17651). the idea is almost too simple. the model writes an answer. then it gives feedback on its own answer. then it rewrites the answer with that feedback. repeat.

across their tasks, this made answers about 20% better on average. there was no retraining. the model only took more passes at the same problem while it worked on it. people call this test-time compute.

## don't let it grade itself

there is a catch for code. in the paper, the model writes its own feedback. ask a model to review its own code with nothing to run, and it tends to tell you what you want to hear. it calls broken code correct, or it finds problems that are not there. both answers sound sure.

the fix is to take the opinion out of the feedback. run the code. a compiler error is not polite. a failing test does not care how good the explanation was. when the feedback comes from running the code, the loop has something true to work with.

so the loop for a coding agent is short. make one small edit. run the build and the tests. if something fails, read the error and fix that one thing. if everything passes, keep the change and move on.

## small steps, and a way back

the loop works best when each step is small. if one edit changes five things and a test fails, you do not know which of the five broke it. if the edit changes one thing, the failure points right at it.

it also helps to have a way back. in december, you type `/rewind` and pick a turn, and your files and the conversation go back to that point. a loop that drifts is cheap when you can undo it.

an agent that checks its work is not smarter than the one that writes in one pass. it just finds out when it is wrong, and it fixes it.
