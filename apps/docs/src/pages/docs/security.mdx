This page tells you how December protects your code, your files, and your API keys.

## Security & Privacy Model

### 1. Safety in the CLI

- Trust prompt: The first time you run `december` in a folder, December asks if you trust it. If you say no, December stops.
- Project folder only: File tools work only inside your project folder. To let December open files outside it, turn on Non-Workspace Access in `/settings`.
- PathGuard: December blocks system folders such as `/etc` and `/usr`, and private key files such as `~/.ssh` and `.pem` files. December asks you before it reads a secrets file such as `.env`.
- Approval for destructive commands: December asks you before it runs a command such as `rm -rf`, `git reset --hard`, or `git push --force`.
- Stop and undo: Press `Ctrl + C` to stop December. Type `/rewind` to revert to an earlier turn.

If you run December with `-y` or `--print`, December approves tool calls without asking. Use these flags only in folders you trust.

### 2. Sandboxes in December Cloud

- One sandbox per session: Each December Cloud session runs in its own sandbox, not on your computer.
- Active limit: You can have 10 running sandboxes. If you start one more, December pauses the one you used least recently.

### 3. API keys

- Direct requests: If you use your own keys, the CLI sends requests straight to the model provider.
- Local storage: The CLI saves your keys in `~/.december/config.json`. Only your user account can read this file (file mode `600`).

### 4. Secrets in December Cloud

A secret is a value that your code needs, such as an API token. December Cloud gives your secrets to the sandbox as environment variables.

1. Open **Settings > Secrets** and select **Add secret**.
2. Type the name, for example `STRIPE_KEY`, and the value.
3. In **Use in**, pick **All repositories** or one repository.
4. Select **Add secret**.

In a session, your code reads the secret as `$STRIPE_KEY`. A secret for one repository goes only to sessions in that repository. If two secrets have the same name, the secret of the repository wins.

### 5. Teams in December Cloud

Open **Settings > Members** to invite people to your team.

1. Select **Invite**, then type the email address of the person.
2. Pick a role: **Admin** or **Member**.
3. Select **Send invite**. The person gets an email with a link. The link works for 7 days.

The owner can change the role of a member. The owner and the admins can invite people, remove a member, and revoke an invite. Team members share nothing yet. Each member keeps their own sessions, secrets, and credits.

The audit log records the changes in the team, such as an invite, a new member, or a role change. The owner and the admins see it. In **Settings > Members**, go to **Audit log** and select **View**. Select **Export CSV** to download it.
