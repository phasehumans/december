This page helps you give December rules that it reads in every session.

## Overview

December reads its rules from one file: `AGENTS.md`. If a folder has no `AGENTS.md`, December reads `CLAUDE.md` in that folder.

Rules tell December your coding standards, team conventions, and project facts, such as the test command. December adds the rules to its instructions for the session. You do not need to repeat them in each prompt.

## Where December looks for rules

December looks in your current folder. Then it looks in each parent folder, up to the root of your file system. In each folder, December reads one file:

- `AGENTS.md`
- `CLAUDE.md`, only if the folder has no `AGENTS.md`

December also reads a global `~/.december/AGENTS.md`. Global rules apply to every project on your computer. If you set `DECEMBER_CONFIG_DIR`, December reads `AGENTS.md` from that folder.

December adds the files in this order: global rules first, then rules from the top folder down to your current folder.

December reads rule files when the CLI starts. If you change a rule file, exit and start `december` again.

December does not read other rule or memory files, such as `.december/memory.md`, `.december/rules.md`, `RULES.md`, or `AGENTS.override.md`. If you have one of these files, move its content to `AGENTS.md`.

## Save a lesson with `/learn`

Use `/learn` when you correct December, or when you find a fact or a procedure that December must remember. December writes the lesson to a file, so that later sessions follow it.

There are two ways to use `/learn`:

- Type `/learn` with no text. December reads the recent conversation and finds the lesson. If there is nothing to save, December tells you and writes no file.
- Type the lesson after the command. For example: `/learn never use axios, use the fetch wrapper in lib/http.ts`.

December saves each lesson in one of two formats:

| Lesson                                                 | Where December saves it                           |
| :----------------------------------------------------- | :------------------------------------------------ |
| A rule, a convention, a preference, or a project fact  | `AGENTS.md` at the root of your git repository    |
| A procedure with many steps, such as a release runbook | A new skill in `.december/skills/<name>/SKILL.md` |

If the root has `CLAUDE.md` and no `AGENTS.md`, December writes to `CLAUDE.md`. If there is no rule file, December makes `AGENTS.md`. If there is no git repository, December uses your current folder.

December reads the file before it writes. It puts the lesson under the heading that fits, and it updates a rule that exists instead of adding a copy. December does not ask before it writes. After it writes, December shows the file path and the lines that it changed.

December applies the change from the next session. To check or undo the change, use `/diff` or `/rewind`.

Note: `AGENTS.md` and skills are often committed to git. December does not write secrets, tokens, or personal data to these files.

## View rules with `/memory`

Type `/memory` to see the rule files that December reads. If December finds more than one file, the view shows all of them. The most specific file is first in the title.

- Press `↑` and `↓` to scroll the file.
- Press `c` to make a starter `AGENTS.md` file. This key shows only when December finds no rule file. December puts the file at the root of your git repository. If there is no git repository, December puts it in your current folder. December does not replace a file that exists.
- Press Esc to close the view.

The view is read only. To change the file, edit it in your editor or use `/learn`.
