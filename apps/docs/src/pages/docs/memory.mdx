This page helps you give December rules and notes that it reads in every session.

## Overview

December reads two types of files when a session starts:

1. Rules: files that you write, such as `AGENTS.md`. Rules tell December your coding standards and team conventions.
2. Memory: a short list of notes in `.december/memory.md`. Memory holds facts about your project, such as the test command.

December adds both to its instructions for the session. You do not need to repeat them in each prompt.

## Workspace memory (`.december/memory.md`)

Memory is a Markdown file with one section for each category. Each entry is one bullet:

```markdown
## build_and_test

- Run unit tests with `bun test`
- Run `bun db:migrate:test` before integration tests

## conventions

- Put custom hooks in the feature folder that uses them
```

The categories are `conventions`, `build_and_test`, `architecture`, `quirks`, `rules`, and `general`.

December can also add and remove entries itself with the `manage_memory` tool, in the terminal and in December Cloud.

### Memory size limit (2 KB)

December adds at most 2,048 bytes of memory to its instructions. If your memory files are larger, December cuts the text at 2 KB. Keep each entry short, and remove entries that are out of date.

The `/memory` view shows a warning when memory is at 85% of the limit or more.

## Manage memory with `/memory`

Type `/memory` to open the memory view. The view has two tabs: `memory` and `rules`. Press Tab to switch between them.

On the `memory` tab:

- Press `a` to add an entry. Type the text, press Tab to select a category, then press Enter.
- Press `d` to remove the selected entry. Press `y` to confirm.
- Press `↑` and `↓` to select an entry.

On the `rules` tab:

- Press `↑` and `↓` to scroll the rule file.
- Press `[` and `]` to switch between rule files, if you have more than one.
- Press `c` to make a starter `AGENTS.md` file. This key shows only when December finds no rule files.

Press Esc to close the view.

## Where December looks for rules

December looks for rule files in your current folder. Then it looks in each parent folder, up to the root of your file system. In each folder, it reads these files:

- `AGENTS.override.md`
- `AGENTS.md`
- `CLAUDE.md`
- `.december/rules.md`
- `.december/AGENTS.md`

December also reads global rules from `~/.december/rules.md` or `~/.december/AGENTS.md`. Global rules apply to every project on your computer.

December adds the files in this order: global rules first, then rules from the top folder down to your current folder. December reads rule files when the CLI starts. If you change a rule file, exit and start `december` again.
